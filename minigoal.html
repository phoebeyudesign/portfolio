MiniGoal:
from saving to doing.

A one-day hackathon project exploring generative UI: an interface that turns a fitness goal into a small, adaptive plan, then reshapes it based on what the person actually does.

MINIGOAL

Designathon overview

Designing for how an interface adapts, not just what it looks like.

I joined a one-day hackathon to understand what “Generative UI” means beyond the buzzword.

Rather than fully understanding the technology first, I wanted to learn by exploring and building.

Baseline

What is generative UI?

The key shift

From predefined flows to adaptive ones.

  • TodayUser → predefined interface → predefined flow → result Everyone gets the same screens.
  • GenUIUser intent → system understands context → interface adapts → result The experience is shaped around the person.

Existing examples

  • Figma Make and LovableBuilding the product: a prompt generates a functional UI or app.
  • ThoughtSpotA dynamic experience within a product: a question generates an analysis or visualisation.

Five opportunity areas

01

Entrance

How does intent enter? Text, voice, image, behaviour, context.

02

Understanding

What does the system think I mean? Intent, context and user needs.

03

Preference

How should I experience it? Visual or text, simple or detailed.

04

Generation

What should appear? AI composes UI from the design system.

Control ties it together: data, rules, design system and AI keep the generated experience accurate.

02

The manifesto

Constraints are the genome.

The hackathon opened with a manifesto that shaped how I thought about the project.

01

Static is a tool limit

We designed identical screens because our tools could only draw one. That is changing.

02

The UI should learn the user

An interface can reshape itself around a person’s context and intent.

03

Generation needs judgement

Every change must be clearer, faster or more useful than what came before.

04

Constraints are the genome

You’re designing the rules and guardrails that generate screens.

The brief

  • Show at least two distinct generations of the same UI
  • Keep the human in control of adaptation
  • Make adaptation a proposal, not a trap
  • Be transparent about what is mocked versus real
03

The problem

Save ≠ act.

I save exercise Reels because I want to try them, but saving doesn’t guarantee I’ll act.

“I want to do this.” “I actually did it.”

The problem isn’t a lack of fitness content. It’s the gap between those two moments. Could a UI turn an existing intention into a small, achievable action, and then learn what helps me follow through?

04

Exploring ideas

Three directions before building.

Idea 01

Save a Reel → generate a workout video.

  • InputA saved Reel Some Reels contain several exercises, others just one.
  • ExploresGenerative content + UI Can saved inspiration become a generated experience?

Idea 02

Goal → voice note → generate a plan.

  • Input“I want to be able to do 8 pull-ups.” The system analyses the goal and generates a structured plan.
  • ExploresIntent → interpretation → generated experience What if the interface is generated from intent, not a predefined flow?

Idea 03

Form corrector.

  • InputVoice note or exercise selection The camera observes movement and gives live audio guidance, such as “Keep your chest up.”
  • ExploresReal-time contextual adaptation Can the interface adapt in real time to what the person is doing?
05

Scoping

One clear generative loop.

The gap between wanting to do something and doing it doesn’t depend on Reels, so I moved the input to a typed goal for Idea 2.

The loop

Intent + context → generated experience → feedback → adaptation.

The first version explored difficulty feedback, behavioural patterns and rescheduling. With two branching flows and per-session logging, it was too much for one day, so I simplified it to one check-in that lets each outcome influence the next generation.

06

Final prototype

A plan that proposes, then adapts.

Type a mini goal into the chat (“I want to do 8 pull-ups”) and the interface proposes a small progression plan: a warm-up, then sets scaled up to the goal. Nothing is added until you tap to accept it.

The plan lives on the home screen as a checklist. Check off a task or two and a “call it a day” button appears, easing tomorrow’s plan. Finish everything and it asks how it felt: too much, keep as is, or push harder.

Choosing “too much” would steer the next plan toward an easier progression, such as supported pull-ups. (This logic is designed but not wired into the live prototype.)

What I learned

Designing rules, not just screens.

This was a one-day hackathon, so there was no formal user testing. Several participants recognised the same “save but never act” pattern, a useful signal but not validation.

Next, I’d want to understand why people don’t act on saved intentions, then keep building MiniGoal and use it myself before validating it with others.
